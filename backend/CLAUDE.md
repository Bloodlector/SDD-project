## Архитектура

- Модуль = папка `src/modules/<name>/`: schemas.ts, repository.ts, service.ts, routes.ts.
- Бизнес-логика только в service. Роут: валидация zod + вызов сервиса + маппинг.
- Запросы к БД только в repository. Сервис не импортирует Prisma напрямую.
- Вход валидируется zod-схемой на границе. Тип берётся из схемы (`z.infer`), не дублируется интерфейсом.
- Наружу отдаём DTO, не строку БД. Явный маппер, лишние поля не протекают.

## Транзакции

- Граница транзакции — в service, через `prisma.$transaction`.
- В роутах и repository транзакций нет.

## Ошибки

- Только типизированные классы из `lib/errors.ts`. Голый `throw new Error` запрещён.
- try/catch в роутах не пишем — работает глобальный error handler.
- Наружу не уходят стектрейсы, тексты Prisma и названия таблиц.

## БД

- Миграции только вперёд: `prisma migrate dev --name <что>`.
- Применённые миграции не редактируем.
- После смены схемы — `prisma generate` (или `postinstall`).

## Тесты

- Vitest. Юнит — сервис с моком репозитория.
- Интеграционные — реальный Postgres, не моки Prisma.
- Тест обязан падать до фикса и проходить после.
