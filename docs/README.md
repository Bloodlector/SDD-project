## Общий обзор

Веб-приложение с системой аутентификации пользователей (регистрация/вход) и интерактивным элементом UI (анимированный кот).

**Ключевые функции:**
- Регистрация пользователя с проверкой уникальности имени
- Авторизация с верификацией учётных данных
- Главный экран с приветствием и кнопкой выхода
- Интерактивный анимированный кот, следующий за курсором

## Архитектура

```
┌─────────────┐     HTTP/JSON     ┌──────────────┐     Prisma      ┌─────────────┐
│   Frontend  │ ────────────────► │   Backend    │ ──────────────► │  PostgreSQL │
│  React +    │   POST /api/auth  │  Fastify +   │   Prisma Client │   (app)     │
│  TypeScript │   POST /health    │  TypeScript  │                 │             │
└─────────────┘                   └──────────────┘                 └─────────────┘
```

**Технологический стек:**
- **Монорепо** на npm workspaces
- **Backend:** Node.js 20+, TypeScript, Fastify, Prisma ORM
- **Frontend:** React 19, TypeScript, Vite
- **База данных:** PostgreSQL
- **Валидация:** Zod
- **Кросс-доменные запросы:** @fastify/cors

## Backend API

### Архитектура модулей

Каждый модуль в `backend/src/modules/<name>/` имеет 4 файла:

| Файл | Назначение |
|------|-----------|
| `schemas.ts` | Zod-схемы валидации входных данных. Типы через `z.infer` |
| `repository.ts` | Запросы к БД через Prisma. Без бизнес-логики |
| `service.ts` | Бизнес-логика. Вызывает repository, бросает `AppError` |
| `routes.ts` | HTTP-роуты. Валидация → вызов сервиса → ответ. Без try/catch |

**Правила:**
- Сервис не импортирует Prisma напрямую
- Роуты не содержат try/catch — работает глобальный error handler
- Наружу отдаются DTO, не записи БД

### Endpoints

#### `GET /health`

Проверка работоспособности сервера.

**Ответ:**
```json
{ "status": "ok" }
```

#### `POST /api/auth/register`

Регистрация нового пользователя.

**Тело запроса:**
```json
{
  "username": "string (мин. 3 символа)",
  "password": "string (мин. 6 символов)"
}
```

**Успешный ответ (201):**
```json
{
  "message": "Регистрация успешна",
  "user": {
    "id": "uuid",
    "username": "string"
  }
}
```

**Ошибки:**
- `400` — Ошибка валидации (`VALIDATION_ERROR`)
- `409` — Имя пользователя занято (`USERNAME_EXISTS`)

#### `POST /api/auth/login`

Авторизация пользователя.

**Тело запроса:**
```json
{
  "username": "string",
  "password": "string"
}
```

**Успешный ответ (200):**
```json
{
  "message": "Авторизация успешна",
  "user": {
    "id": "uuid",
    "username": "string"
  }
}
```

**Ошибки:**
- `400` — Ошибка валидации (`VALIDATION_ERROR`)
- `401` — Пользователь не найден (`USER_NOT_FOUND`)
- `401` — Неверный пароль (`INVALID_PASSWORD`)

## Frontend

### Архитектура

| Папка | Назначение |
|-------|-----------|
| `src/features/<feature>/` | Фичи: компоненты, хуки, логика |
| `src/api/` | Единственное место для fetch-вызовов |
| `src/components/` | Переиспользуемые компоненты (без знания о фичах) |

**Правила:**
- Никаких fetch/axios в компонентах — только через `src/api/`
- Локальное `useState`, глобальный стор — только по просьбе

### Компоненты

#### `Auth` (`frontend/src/features/auth/Auth.tsx`)

Фича аутентификации, управляющая состоянием входа/регистрации.

**Зависимости:**
- `src/api/auth.ts` — все API-вызовы (fetch)
- `src/components/Cat.tsx` — анимированный кот

**Состояния:**
1. **Форма входа** — поля "Имя пользователя" и "Пароль", кнопка "Войти", ссылка "Зарегистрироваться"
2. **Модальное окно регистрации** — поля "Имя пользователя" и "Пароль", кнопка "Зарегистрироваться", кнопка "Закрыть"
3. **Главный экран** — приветствие пользователя, кнопка "Выйти" (правый верхний угол), анимированный кот

**Логика:**
- Вызовы API через `src/api/auth.ts` (`login`, `register`)
- Ошибки отображаются под формой
- Состояние загрузки блокирует кнопки
- При успешной авторизации показывается главный экран
- При успешной регистрации — возврат к форме входа

#### `Cat` (`frontend/src/components/Cat.tsx`)

Интерактивный SVG-кот, следующий за курсором мыши.

**Поведение:**
- Кот движется к позиции курсора с плавной анимацией
- При движении анимируются лапы
- Кот разворачивается в сторону движения
- Если курсор покидает окно — кот возвращается к миске
- Использует `requestAnimationFrame` для плавности

## База данных

### Схема

**Таблица `User`:**

| Поле        | Тип                    | Описание              | Ограничения           |
|-------------|------------------------|-----------------------|-----------------------|
| `id`        | UUID                   | Уникальный идентификатор | PRIMARY KEY, DEFAULT gen_random_uuid() |
| `username`  | VARCHAR(255)           | Имя пользователя      | UNIQUE, NOT NULL, INDEX |
| `password`  | VARCHAR(255)           | Пароль                | NOT NULL              |
| `createdAt` | TIMESTAMP WITH TIME ZONE | Дата создания       | DEFAULT NOW()         |
| `updatedAt` | TIMESTAMP WITH TIME ZONE | Дата обновления     | AUTO-UPDATE           |

**Подключение:**
- URL: `postgresql://app:app@localhost:5432/app`
- Конфигурация в `backend/.env` (переменная `DATABASE_URL`)
- ORM: Prisma Client с адаптером `@prisma/adapter-pg`

## Установка и запуск

### Требования

- Node.js >= 20
- PostgreSQL (запущенный на `localhost:5432`)
- База данных `app` с пользователем `app/app`

### Установка

```bash
# Установка зависимостей
npm ci
```

### Запуск

```bash
# Backend (dev mode с hot-reload)
npm run dev:backend

# Frontend (Vite dev server)
npm run dev:frontend
```

### Миграции базы данных

```bash
# Создание/применение миграций
npm run db:migrate
```

> **Важно:** При первом запуске необходимо создать таблицу `User` вручную или через миграцию Prisma.

### SDD-процесс

Проект следует методологии SDD (Specification-Driven Development):

1. **Spec** — описание проблемы, сценариев, критериев приёмки
2. **Plan** — подход, файлы, контракт API, риски
3. **Tasks** — атомарные задачи (одна задача ≈ один коммит)
4. **Implement** — реализация по задачам

Шаблоны: `docs/sdd.md`

### Правила разработки

- Не добавлять зависимости без разрешения
- `any` запрещён, использовать `unknown` + проверку
- Импорты типов — через `import type`
- Промисы всегда `awaited` или `void` с комментарием
- Не менять применённые миграции
- Новые миграции — только новые файлы

### Структура ответов API

**Успех:**
```json
{ "message": "...", "user": { "id": "...", "username": "..." } }
```

**Ошибка:**
```json
{ "code": "ERROR_CODE", "message": "..." }
```

### Безопасность (важно)

> **Внимание:** Пароли хранятся в открытом виде. Для production необходимо добавить хеширование через `bcrypt` или аналог.
