# SDD — как мы работаем

## Цикл

1. `/spec <фича>` → `specs/NNN-<слаг>/spec.md`. Отвечаю на «Открытые вопросы».
2. `/plan` → plan.md. Согласую.
3. `/tasks` → tasks.md. Согласую.
4. `/implement` → код по задачам.

## Железные правила

- В `spec.md` нет слов о технологиях. Ни React, ни Prisma, ни Postgres.
  Только поведение и проверяемые критерии.

2. Каждая задача — атомарная, проверяемая отдельно. Одна задача ≈ один коммит.
3. Спека меняется в том же коммите, что и поведение. Иначе она врёт.
4. Блок «Вне скоупа» обязателен. Это защита от импровизации.
5. Агент не выходит за план. Нужен новый файл — стоп.
